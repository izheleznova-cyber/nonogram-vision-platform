# Object Ownership Map

## Назначение

Документ определяет отношения между сущностями Lesson Designer.

Используются три вида связей.

◆ Композиция (владеет)

Жизненный цикл дочернего объекта полностью определяется родителем.

При удалении родителя удаляется и дочерний объект.

---

→ Ссылка

Объект не принадлежит владельцу.

Владелец хранит только ссылку.

Удаление владельца не удаляет объект.

---

○ Независимая сущность

Объект существует самостоятельно.

Может использоваться многими другими объектами.

---

# Главное архитектурное правило

Lesson владеет только структурой урока.

Task владеет только описанием задания.

Asset никогда не принадлежит Lesson.

Asset может одновременно использоваться
любыми уроками.

Все учебные ресурсы существуют
независимо от Lesson Designer.


Это карта композиции.

├── Passport
└── Preview

а не

Asset
Passport
Preview

То есть:

Lesson владеет Stage;
Stage владеет Task;
Task владеет AssetRef и AnswerSpec;
AssetRef только ссылается на Asset;
Asset уже внутри себя содержит Passport и Preview.




# Lesson Designer Domain Glossary

## Назначение

Данный документ определяет терминологию Lesson Designer.

Все архитектурные решения, модели данных и программный код должны использовать определения, приведённые ниже.

Если появляется новая сущность, она сначала добавляется в данный документ, а затем реализуется в коде.

---

# Lesson

Учебный сценарий.

Lesson является корневой сущностью Lesson Designer.

Lesson объединяет этапы урока, содержит общие параметры и правила оценивания.

Lesson не хранит состояние прохождения урока.

---

# Stage

Логический этап урока.

Stage объединяет несколько заданий общей целью.

Этап определяет порядок выполнения заданий, ограничения и условия завершения.

---

# Task

Минимальная учебная единица.

Task описывает одно действие, которое должен выполнить студент.

Task не содержит состояние выполнения.

---

# Asset

Учебный ресурс.

Asset существует независимо от уроков.

Asset может использоваться в любом количестве заданий.

Примеры:

- японский кроссворд;
- изображение;
- текст;
- видео;
- аудиофайл.

---

# AssetRef

Ссылка на Asset.

AssetRef используется внутри Task.

AssetRef не содержит ресурс.

AssetRef содержит только информацию,
необходимую для получения Asset.

---

# AnswerSpec

Описание ожидаемого результата.

AnswerSpec определяет,
что считается правильным ответом.

AnswerSpec не выполняет проверку.

---

# Rubric

Правила оценивания урока.

Rubric описывает,
как должен вычисляться итоговый результат.

Rubric не хранит результаты студентов.

---

# Criterion

Отдельный критерий оценивания.

Criterion входит в Rubric.

Каждый Criterion имеет собственный вес
или собственное правило оценки.

---

# Manifest

Описание структуры урока.

Manifest является сериализованным представлением Lesson.

Manifest не содержит результаты выполнения.

---

# Passport

Описание учебного ресурса.

Для японских кроссвордов Passport содержит:

- размеры;
- категорию;
- автора;
- признаки изображения;
- исследовательские параметры;
- другую метаинформацию.

Passport формируется PassportDatabase.

---

# Preview

Миниатюра учебного ресурса.

Preview используется Lesson Builder
для предварительного просмотра задания.

Preview создаётся Renderer.

---

# Renderer

Подсистема формирования изображений.

Renderer строит:

- миниатюры;
- изображения кроссвордов;
- изображения для интерфейса.

Renderer ничего не знает
об уроках и студентах.

---

# PassportDatabase

Хранилище учебных ресурсов.

PassportDatabase отвечает за:

- загрузку ресурсов;
- хранение паспортов;
- поиск ресурсов.

PassportDatabase не знает
о структуре уроков.

---

# Lesson Builder

Подсистема Teacher Platform.

Отвечает на вопрос:

    Какие задания войдут в урок?

Builder формирует Lesson.

Builder не определяет,
как студент будет проходить урок.

---

# Lesson Designer

Подсистема Teacher Platform.

Отвечает на вопрос:

    Как должен проходить урок?

Lesson Designer описывает сценарий урока.

Lesson Designer не выполняет урок.

---

# Monitor

Подсистема выполнения урока.

Monitor отвечает на вопрос:

    Как студент проходит урок?

Monitor:

- загружает Lesson;
- отслеживает выполнение;
- проверяет ответы;
- вычисляет оценки;
- сохраняет статистику.

---

# Student Platform

Подсистема выполнения заданий.

Student Platform предоставляет интерфейс студенту.

Student Platform не изменяет структуру Lesson.

---

# Research

Режим исследовательского анализа.

Research определяет,
какие наблюдения необходимо выполнить
во время прохождения урока.

Например:

- момент узнавания объекта;
- изменение гипотез;
- определение эмоции;
- распознавание лица.

Research описывает эксперимент,
но не хранит его результаты.

---

# Hypothesis

Предположение студента
о содержимом изображения.

Hypothesis является частью исследования.

Monitor фиксирует
последовательность гипотез студента.

---

# Profiling

Описание признаков изображения,
которые должен определить студент.

Например:

- пол;
- возраст;
- эмоция;
- направление взгляда;
- наличие очков;
- наличие бороды.

Profiling используется
для исследовательских уроков.

---

# Completion Rule

Правило завершения задания
или этапа.

Например:

- 100 % решения;
- 95 % решения;
- обязательная проверка;
- ограничение времени.

---

# Validation

Проверка корректности Lesson.

Validator проверяет:

- целостность структуры;
- существование ссылок;
- корректность manifest;
- отсутствие ошибок конфигурации.

Validation не проверяет
ответы студентов.

# Главный принцип

Lesson Designer описывает урок.

Monitor выполняет урок.

Student Platform предоставляет интерфейс выполнения.

PassportDatabase предоставляет учебные ресурсы.

Каждая подсистема отвечает только за свою область ответственности.
